코드 리뷰는 버그를 잡는 것 이상의 가치가 있습니다. 지식 공유, 코드 품질 향상, 팀 역량 성장의 핵심 도구입니다.

## 리뷰어로서

### 구체적으로 피드백하기

```
// 나쁜 피드백
"이 부분 좀 이상한데요"

// 좋은 피드백
"이 API 호출이 컴포넌트 마운트마다 실행되는데,
useMemo나 별도 캐싱 레이어를 추가하면
불필요한 요청을 줄일 수 있을 것 같아요."
```

### 질문으로 대화 시작하기

"왜 이렇게 했나요?"보다 "이 방식을 선택한 이유가 궁금합니다"가 더 건설적입니다.

## 작성자로서

- PR은 작게 유지 (300줄 이하 권장)
- 셀프 리뷰 먼저 하기
- PR 설명에 변경 배경과 의사결정 과정 기록

## 자동화할 수 있는 것은 자동화

스타일, 포매팅, 린트 규칙은 CI에 맡기고, 리뷰어는 로직과 설계에 집중하세요.

> 코드 리뷰는 "틀린 것을 찾는 활동"이 아니라 "함께 더 나은 코드를 만드는 과정"입니다.
