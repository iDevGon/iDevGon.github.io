# Sync Docs

프로젝트 구조와 코드를 분석하여 문서를 현재 상태에 맞게 최신화하는 스킬입니다.

## 역할

당신은 프로젝트 문서화 전문가입니다. 프로젝트의 실제 코드와 구조를 정밀하게 분석한 뒤, 문서를 정확하고 간결하게 갱신합니다. 추측하지 않으며, 실제 코드에서 확인한 정보만 반영합니다.

## 대상 파일

| 파일 | 용도 |
|------|------|
| `README.md` | 프로젝트 소개, 구조, 기술 스택, 개발 가이드 |
| `.agents/AGENTS.md` | AI 에이전트를 위한 개발 가이드라인 |

## 실행 절차

### 1. 인자 확인

- `readme`: README.md만 갱신
- `agents`: .agents/AGENTS.md만 갱신
- 인자 없음: 두 파일 모두 갱신

### 2. 프로젝트 구조 탐색

아래 항목을 **실제 코드에서** 수집합니다. Agent(Explore) 도구를 활용하여 병렬로 탐색합니다.

#### 2-1. 워크스페이스 구조

- 루트 `pnpm-workspace.yaml` 읽기
- 각 워크스페이스 패키지의 `package.json` 읽기 (이름, 버전, 스크립트, 의존성)
- 루트 `package.json`의 스크립트 및 overrides 확인

#### 2-2. apps/blog 분석

- **라우트**: `apps/blog/src/routes/` 하위 파일 목록으로 전체 라우트 구조 파악
- **컴포넌트**: `apps/blog/src/components/` 하위 파일 목록
- **아티클**: `apps/blog/src/articles/*.md` 파일 수 및 태그 목록
- **스토어**: `apps/blog/src/store/` 의 상태 구조
- **유틸리티**: `apps/blog/src/utils/` 의 주요 함수
- **설정 파일**: `vite.config.ts`, `panda.config.ts`, `tsconfig.app.json`의 핵심 설정

#### 2-3. packages/design-system 분석

- `src/components/index.ts`에서 export되는 컴포넌트 목록
- `src/preset.ts`에서 정의된 토큰, 브레이크포인트, 시맨틱 토큰, 키프레임 확인

#### 2-4. packages/icons 분석

- `src/index.ts`에서 export되는 아이콘 목록

#### 2-5. 설정 파일 분석

- `biome.json`: 린팅/포매팅 주요 규칙
- `.github/workflows/deploy.yml`: 배포 프로세스
- 루트 `tsconfig.json`: 프로젝트 레퍼런스

#### 2-6. 스킬 목록

- `.agents/skills/` 하위 디렉토리별 SKILL.md의 name과 description 수집

### 3. 현재 문서 읽기

- 기존 `README.md`와 `.agents/AGENTS.md`를 읽습니다.
- 기존 문서의 **구조와 톤**을 유지하면서 내용만 갱신하는 것이 원칙입니다.

### 4. 변경점 도출

수집한 정보와 기존 문서를 비교하여 변경이 필요한 항목을 식별합니다:

- 새로 추가된 패키지, 컴포넌트, 아이콘, 라우트, 스킬
- 삭제된 항목
- 이름이나 경로가 변경된 항목
- 기술 스택 변경 (의존성 추가/제거)
- 스크립트 변경

### 5. 결과 출력 및 확인

변경점을 아래 형식으로 출력합니다:

```
## 📋 문서 갱신 대상

### README.md
| # | 섹션 | 변경 유형 | 내용 |
|---|------|-----------|------|
| 1 | 프로젝트 구조 | 추가 | LogoIcon 아이콘 추가 반영 |
| 2 | 기술 스택 | 수정 | Vite 버전 업데이트 |

### .agents/AGENTS.md
| # | 섹션 | 변경 유형 | 내용 |
|---|------|-----------|------|
| 1 | 패키지 참조 | 추가 | Pagination 컴포넌트 추가 |
```

변경점이 없으면 "문서가 최신 상태입니다"를 출력하고 종료합니다.

사용자에게 적용 여부를 확인합니다:
- **전체 적용**: 모든 변경사항 반영
- **선택 적용**: 항목별 수락/거부
- **적용 안 함**: 결과만 확인

### 6. 문서 갱신

Edit 도구를 사용하여 문서를 수정합니다.

#### README.md 갱신 규칙

- 기존 섹션 구조를 유지합니다 (프로젝트 구조, 기술 스택, 로컬 개발, 배포 등).
- 프로젝트 구조 트리는 실제 디렉토리 구조를 반영합니다.
- 기술 스택 테이블은 실제 의존성과 일치시킵니다.
- 스크립트 목록은 루트 `package.json`에서 가져옵니다.
- 한국어로 작성합니다.

#### .agents/AGENTS.md 갱신 규칙

- 기존 섹션 구조를 유지합니다 (프로젝트 개요, 빌드 & 실행, 기술 스택 & 컨벤션, 주의사항, 배포 등).
- **워크스페이스 구조**: 실제 패키지 이름과 설명을 반영합니다.
- **라우팅**: 실제 라우트 파일 구조를 반영합니다.
- **스타일링**: 디자인 토큰, 브레이크포인트, 컬러 모드 조건 등 최신 정보를 반영합니다.
- **컴포넌트 목록**: design-system에서 export되는 컴포넌트를 정확히 나열합니다.
- **아이콘 목록**: icons 패키지에서 export되는 아이콘을 정확히 나열합니다.
- **경로 별칭**: tsconfig에서 정의된 alias를 반영합니다.
- **주의사항**: 자동 생성 파일, override 설정 등을 최신화합니다.
- 한국어로 작성합니다.

### 7. 검증

갱신된 문서를 다시 읽어서 아래 사항을 확인합니다:

- 마크다운 문법이 올바른지
- 실제 코드와 불일치하는 내용이 없는지
- 섹션 간 중복 내용이 없는지

문제가 발견되면 즉시 수정합니다.
