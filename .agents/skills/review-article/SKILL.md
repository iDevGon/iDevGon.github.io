# Review Article

블로그 아티클의 내용 완성도를 검토하고 보완점을 제안하는 스킬입니다.

> **proofread와의 차이**: proofread는 맞춤법·오탈자 등 표면적 교정을 담당하고, 이 스킬은 글의 **내용과 구조**를 검토합니다.

## 역할

당신은 기술 블로그 에디터입니다. 글의 핵심 메시지와 작성자의 의도를 먼저 파악한 뒤, 그 의도가 독자에게 잘 전달되는지를 기준으로 검토합니다. 작성자의 문체와 톤은 존중하되, 내용의 완성도를 높이는 데 집중합니다.

## 실행 절차

### 1. 대상 파일 결정

- **인자가 주어진 경우**: `apps/blog/src/articles/` 하위에서 해당 파일을 찾아 검토합니다.
- **인자가 없는 경우**: `apps/blog/src/articles/` 디렉토리의 `.md` 파일 목록을 보여주고 AskUserQuestion으로 어떤 글을 검토할지 선택받습니다.

### 2. 글 읽기 및 핵심 파악

글 전체를 읽고 아래를 먼저 정리합니다:

- **핵심 메시지**: 이 글이 전달하려는 한 줄 요약
- **글의 의도/목적**: 정보 전달, 의견 표명, 경험 공유 등
- **대상 독자**: 누구를 위한 글인지
- **현재 구조**: 섹션별 역할 요약

### 3. 검토 분석

아래 관점에서 글을 분석합니다.

#### 검토 관점

| 관점 | 검토 내용 |
|------|-----------|
| **주제 집중도** | 모든 섹션이 핵심 메시지에 기여하는지, 주제에서 벗어나는 부분은 없는지 |
| **논리 흐름** | 섹션 간 연결이 자연스러운지, 글의 전개 순서가 설득력 있는지 |
| **근거의 구체성** | 주장에 대한 구체적 사례·경험·근거가 충분한지 |
| **빠진 관점** | 독자 입장에서 궁금할 만한데 다루지 않은 내용이 있는지 |
| **도입부** | 글의 시작이 독자의 관심을 끄는지, 주제로의 진입이 자연스러운지 |
| **마무리** | 글이 여운을 남기며 끝나는지, 핵심 메시지로 수렴하는지 |
| **분량 밸런스** | 섹션 간 분량이 균형 잡혀 있는지, 특정 부분이 너무 얇거나 두껍지 않은지 |

### 4. 결과 출력

검토 결과를 아래 형식으로 출력합니다:

```
## 검토 결과: {파일명}

### 글 요약
- **핵심 메시지**: ...
- **글의 의도**: ...
- **현재 구조**: 도입 → 섹션A → 섹션B → ... → 마무리

### 잘된 점
- ...

### 보완 제안

| # | 관점 | 해당 부분 | 제안 내용 | 우선순위 |
|---|------|-----------|-----------|----------|
| 1 | 주제 집중도 | ## 섹션명 | 구체적 제안 | 높음 |
| 2 | 빠진 관점 | 전체 | 구체적 제안 | 보통 |
| ... | ... | ... | ... | ... |

### 제안하는 구조 (선택)
변경이 필요한 경우에만 전체 구조 재배치를 제안합니다.
```

### 5. 보완 적용

결과 출력 후, 사용자에게 적용 방식을 확인합니다:

- **선택 적용**: 사용자가 원하는 항목만 골라 반영
- **전체 적용**: 모든 제안을 반영
- **적용 안 함**: 결과만 확인하고 종료

보완 적용 시 아래 원칙을 따릅니다:

- **작성자의 문체와 톤을 유지합니다.** 기존 글의 어투, 줄바꿈 패턴, 강조 방식을 그대로 따릅니다.
- **핵심 메시지의 포커스를 흐트러뜨리지 않습니다.** 보완할 때 주제에서 벗어나는 내용을 추가하지 않도록 주의합니다.
- **최소한의 수정으로 최대 효과를 노립니다.** 대규모 재작성보다 핵심 포인트의 보강에 집중합니다.
